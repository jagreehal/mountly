`tests/adapter-parity.spec.ts` drives all three adapters through the same
browser checks. What that suite covers is what this page promises. Anything
below the line is behaviour we describe but do not pin.

## Covered by the parity suite

- `mount(container, props)` mounts widget UI.
- `unmount(container)` tears down widget UI.
- `update(container, props)` is available on all three adapters.
- Light DOM mounting by default.
- Opt-in shadow DOM via `shadow: true`.
- `shadowMode: "open" | "closed"` support.
- Automatic light-DOM fallback when a container can't host a shadow root.

## Where the three differ

`update()` keeps the component instance alive on all three, so local state
survives a prop change. How each gets there differs:

- React: re-renders on the existing root.
- Vue: patches a reactive props object the adapter owns.
- Svelte 4: calls `$set` on the instance. Svelte 5: patches a `$state` props
  object, unless you passed your own `mount`/`unmount`, in which case the
  adapter assigns onto the mount handle and reaches exported bindings only.

A prop the host stops sending clears on Vue and Svelte 5. React sees the props
object it is given.

## Scope

Parity here is about mountly adapter contract behavior, not framework internals (e.g. React hooks reconciliation semantics vs Vue/Svelte instance replacement semantics).
